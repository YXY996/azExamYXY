# 本地持久化、题目版本与练习记录

## 目标

第二阶段把浏览器临时状态迁移到本机 SQLite，使审核结果、已发布题目版本、练习会话和作答记录在刷新或更换设备访问同一服务时仍然存在。

数据库位于 `apps/web/data/private/az-exam-coach.sqlite`，由 Git 忽略。当前使用固定的本地单用户身份；对公网部署前必须增加登录、会话验证和用户级数据隔离。

## 数据边界

- `question_drafts` 保存可变审核草稿并使用 `lock_version` 防止两个页面互相覆盖。
- `question_revisions` 保存批准后不可变的题目内容版本。
- `answer_keys` 与具体题目版本一一绑定，并保存答案来源。
- `review_events` 追加记录保存与批准事件。
- `practice_sessions` 与 `practice_items` 固定练习开始时使用的题目版本。
- `answer_events` 追加保存作答事实；后续修改题目不会重算旧成绩。

## 审核流程

1. 编辑题干、选项、题型、正确答案和答案来源。
2. 保存草稿时提交当前 `lock_version`。
3. 服务端发现版本不一致时返回 409，客户端不得静默覆盖。
4. 批准请求在单个数据库事务中执行发布门禁。
5. 成功后同时创建不可变 revision、answer key 和 review event。

批准门禁至少检查：题型受支持、题干非空、至少两个有效且不重复的选项、正确答案引用现有选项、答案数量符合题型、答案来源可追溯，以及没有阻塞型质量标记。

## 练习流程

开始练习时，服务端为所有当前已批准题目固定 revision 和 answer key。发给练习界面的题目内容不包含正确答案；提交选择后由服务端评分并返回本题结果。

练习接口会恢复尚未完成的会话。每个练习 item 只能形成一条最终作答记录，避免重复点击造成重复计分。全部题目完成后，会话状态变为 `completed` 并保存完成时间。

## 迁移方向

当前 SQL 使用 UUID、UTC ISO 时间和普通表结构，避免 SQLite 专用 trigger。迁移 PostgreSQL 时将 JSON TEXT 改为 `jsonb`、时间改为 `timestamptz`，并用真实用户表替换固定本地 owner。
